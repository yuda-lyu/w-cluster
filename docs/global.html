alternating(mat, med, maxiter) → {Object}

Description:

  • Run the Alternating algorithm, a k-means-style alternate optimization.

    This is fairly fast (O(n²), like the FasterPAM method), but because the newly chosen medoid must cover the entire existing cluster, it tends to get stuck in worse local optima as the alternatives. Hence, it is not really recommended to use this algorithm (also known as "Alternate" in classic facility location literature, and re-invented by Park and Jun 2009).

applyEma(C, usage, sums, counts, k, d, alpha)

Description:

  • 以一個批次之統計對質量與中心做一次EMA更新(論文式2~4, 以質量N_j與中心c_j=S_j/N_j表示)

    全部群之質量先衰減為(1-alpha)N_j; 批次中有被指派之群(n_j>0)再得 N_j <- N_j + alphan_j, 中心朝該群批次平均移動 weight = alpha*n_j/N_j 之比例; 未被指派之群中心不動(其質量衰減, 對應S_j與N_j同比衰減使比值不變)

    對照: 參考實作e_means.py:456-505 _apply_statistics; alpha為1時不衰減舊質量, 被指派之群質量改為alpha*n_j(replace_usage, e_means.py:489-496)

let mat = [
    [40, 50, 60],
    [50, 70, 60],
    [80, 70, 90],
    [50, 60, 80]
]
let res = await WCluster.cluster(mat, { mode: 'k-medoids', kNumber: 2, nCompNIPALS: 2 })

let resE = await WCluster.cluster(mat, { mode: 'e-means', kNumber: 2, nCompNIPALS: 2, seed: 0 })
console.log(resE.ginds)
// => [ [ 1, 2, 3 ], [ 0 ] ]

//init: e-means預設為隨機初始化(論文作法)，群分離明顯之資料可能落入局部解(此例seed為1時一群含兩個中心)；init為'k-means++'時改用貪婪k-means++
let rows = []
for (let i = 0; i < 300; i++) {
    let g = i % 3
    rows.push([g * 10 + (i % 7) * 0.1, g * -5 + (i % 11) * 0.05, (i % 13) * 0.02 + g])
}
let resR = await WCluster.cluster(rows, { mode: 'e-means', kNumber: 3, seed: 1 })
console.log(resR.ginds.map((g) => g.length))
// => [ 200, 48, 52 ]
let resK = await WCluster.cluster(rows, { mode: 'e-means', kNumber: 3, seed: 1, init: 'k-means++' })
console.log(resK.ginds.map((g) => g.length))
// => [ 100, 100, 100 ]
